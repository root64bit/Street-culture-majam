# STREET CULTURE — Backend Completeness Report

Generated on 8 October 2026 against the verified local schema (47 migrations, 36 RLS-enabled public tables, 1 security-invoker catalog view, 75 public functions, 56 user triggers, 92 public indexes) and full automated test suite.

Status definitions per Phase 58:
- **COMPLETE**: Backed by PostgreSQL schema, RLS/RPC authorization, audit logging, server-rendered UI/API routes, and automated tests.
- **PARTIAL**: Operational for the core workflow, with documented scope boundaries or external dependencies noted explicitly.
- **MISSING**: Not implemented.
- **UNUSED**: Present in the schema for future extensibility, not actively used by storefront/admin runtime.

## Domain Completeness Matrix

| Domain | Status | Evidence & Operational Summary |
| --- | --- | --- |
| **Auth** | **COMPLETE** | Supabase SSR cookie auth (`src/lib/supabase/server.ts`, `middleware.ts`), sign-in, sign-up, forgot/reset password, change password, callback route, and suspended/banned account guards (`guard_suspended_account_new_commerce`, `admin_access_disabled`). |
| **Roles** | **COMPLETE** | 9 operational roles (`SUPER_ADMIN`, `ADMIN`, `OPERATIONS_MANAGER`, `CATALOG_MANAGER`, `AUTHENTICATOR`, `FULFILLMENT`, `FINANCE`, `SUPPORT`, `STAFF`) plus `SELLER` and `CUSTOMER`. Mapped to 32 granular capabilities in `public.role_capabilities`, enforced by `has_capability()`, `my_capabilities()`, `requireCapabilitiesPage()`, and `capabilityApiClient()`. Role assignment/removal and admin access revocation are `SUPER_ADMIN`-only via audited RPCs (`manage_staff_role`, `set_staff_admin_access`). |
| **Catalog** | **COMPLETE** | Security-invoker `public_catalog_listings` view exposes only `LIVE` + `PASSED` + `MZN` + `quantity = 1` + active unarchived products and active brands/categories. Dedicated `/admin/brands` and `/admin/categories` modules with hierarchy cycle protection (`save_admin_configuration`). Homepage features the interactive Most Wanted carousel. |
| **Products** | **COMPLETE** | `/admin/products` supports server-side search, brand/category/status/stock/featured/most-wanted filters, sorting, pagination, bulk actions (`feature`, `unfeature`, `most_wanted`, `remove_most_wanted`, `archive`, `restore`), and `.xlsx` export. `/admin/products/[id]` provides 7 tabs: General, Variants, Media, Listings, Pricing, SEO, History. |
| **Variants** | **COMPLETE** | `/admin/products/[id]?tab=variants` supports creating/editing variants (`size`, `size_system`, `color`, `sku`, `price_override`, `active`) and range generation (`generate_product_size_range`, e.g., US `7` to `13` step `0.5`) without inventing physical inventory. Deactivating a variant with `LIVE`/`RESERVED` stock is blocked by database trigger (`guard_variant_deactivation`). |
| **Media** | **COMPLETE** | Product workspace media manager (`/admin/products/[id]?tab=media`) supports upload, alt text, primary photo (`sort_order = 0`), reordering, and removal guard when a product has live stock. `/admin/media` manages `product-images`, `brand-assets`, and `editorial-assets` with usage inspection (`admin_public_media_library`) and blocks deletion of referenced assets (`public_asset_is_unused`). Private `authentication-evidence` is never exposed publicly. |
| **Listings** | **COMPLETE** | One-of-one physical unit model (`quantity = 1`, `currency = 'MZN'`). Store-owned additions via `create_staff_inventory_draft` always start as `DRAFT` + `PENDING` authentication even on live products. Consignment listings are created only from `AUTHENTICATED`/`PHOTOGRAPHY`/`PRICING` submissions via `create_consignment_listing`. |
| **Inventory** | **COMPLETE** | `/admin/inventory` provides server-paged filtering across all listing states (`DRAFT`, `PENDING_REVIEW`, `APPROVED`, `LIVE`, `RESERVED`, `SOLD`, `REJECTED`, `EXPIRED`, `ARCHIVED`, `UNAVAILABLE`) and audited operations via `manage_inventory_listing` (`ACTIVATE`, `DEACTIVATE`, `ARCHIVE`, `RESTORE`, `ADJUST_PRICE`, `RELEASE_EXPIRED`). Reserved and sold listings are immutable against price/archive edits. |
| **Cart** | **PARTIAL (Client State) / UNUSED (DB Tables)** | Storefront cart is persisted in client localStorage and validated server-side against live database listings via `/api/cart/validate` and at checkout via `create_guest_checkout_order`. The `carts`, `cart_items`, and `offers` tables are RLS-protected for own-user access but unused by the active checkout flow. |
| **Checkout** | **COMPLETE** | One-page MZN checkout (`create_guest_checkout_order`) uses PostgreSQL `FOR UPDATE` row locking to reserve one-of-one listings for 15 minutes, verifies exact expected prices, validates active shipping methods from `shipping_methods`, and prevents double-reservation under concurrent requests. |
| **Orders** | **COMPLETE** | `/admin/orders` (`admin_order_workspace`) supports search by order number/email/phone/payment reference, status/payment/fulfillment/date filters, and pagination. `/admin/orders/[id]` supports audited fulfillment transitions (`transition_order_fulfillment`, including `PACKED` and `READY_FOR_PICKUP`), private operator notes (`order_operator_notes`), unpaid cancellation, refund requests (`order_refund_requests`), and finance-only external refund attestation (`review_order_refund`). |
| **Payments** | **COMPLETE** | Server-only MineScope M-Pesa integration. Accepted push requests remain `PENDING` until provider confirmation. `/admin/payments`, `/admin/payments/[id]`, and `/admin/payments/reconciliation` display redacted provider metadata (`redactPaymentMetadata`), flag mismatches (`reconciliation_needs_review`), allow operator review resolution (`resolve_payment_review_flag`), and run audited provider queries (`record_provider_reconciliation`). Includes protected daily cron endpoint `/api/cron/payments`. There is no arbitrary admin "mark paid" button. |
| **Shipping** | **COMPLETE** | `/admin/shipping` manages `shipping_methods` (`code`, `name`, `country_code`, `region`, `price`, `currency`, `estimated_min_days`, `estimated_max_days`, `active`) via `save_admin_configuration`. Storefront checkout reads active methods dynamically via `/api/checkout/shipping`. |
| **Consignments** | **COMPLETE** | End-to-end workflow from seller MZN submission (`/consign/new`) through `/admin/consignments` and `/admin/consignments/[id]`: `transition_consignment` (`START_REVIEW`, `REQUEST_INFO`, `APPROVE`, `REJECT`, `AWAIT_ITEM`, `MARK_RECEIVED`, `SEND_TO_AUTH`), seller response to info requests (`respond_to_consignment_info_request`), canonical listing creation (`create_consignment_listing`), and return handling (`record_consignment_return`) with store-configured return instructions (`operational_store_context`). |
| **Authentication** | **COMPLETE** | `/admin/authentication` and `/admin/authentication/[id]` provide human physical inspection: configurable checklist (`authentication_inspection_template`), serial/style-code review, comparison notes, priority, reviewer assignment (`save_authentication_inspection`), private evidence uploads to `authentication-evidence` (`attach_authentication_evidence`), and audited decisions (`decide_consignment_authentication`). Database trigger `guard_authentication_checklist` requires all recorded checklist items to be true before `PASS`. |
| **Commission** | **COMPLETE** | `/admin/commissions` manages `commission_rules` (`seller_type`, `brand_id`, `category_id`, `percentage`, `fixed_fee`, `minimum_fee`, `currency`, `priority`, `starts_at`, `ends_at`, `active`) with an interactive commission calculator preview. Default platform consignment rule is 30% (`calculate_order_item_commission`). |
| **Payouts** | **COMPLETE** | Automatic creation of one `PENDING` payout per sold consignment `order_item` upon confirmed payment (`complete_guest_checkout_payment`); own-stock sales create zero payouts. `/admin/payouts` enforces `transition_seller_payout` (`APPROVE`, `MARK_PROCESSING`, `MARK_PAID`, `MARK_FAILED`, plus failure recovery `FAILED -> APPROVED`). Marking `PAID` requires `payouts.mark_paid` (Finance), payment method, unique external reference, and operator note, and updates the consignment status to `PAID`. |
| **Imports** | **PARTIAL (Create-Only by Design)** | `/admin/imports` and `/admin/imports/[id]` provide dynamic `.xlsx` template generation (`/api/admin/imports/template` with `PRODUCTS`, `VARIANTS`, `MEDIA`, `INSTRUCTIONS`, `REFERENCE VALUES`), workbook upload, dry-run validation, staging in `product_import_batches` / `product_import_rows`, preview with per-row error/fix suggestions, error workbook download (`/api/admin/imports/[id]/errors`), and transactional per-product commit (`commit_product_import_row`) as `DRAFT`/`PENDING` own-stock. Create-only by design so imports never overwrite or auto-publish live inventory. |
| **Notifications** | **PARTIAL (In-App Complete; External Delivery Dev-Only)** | Customer notifications (`public.notifications`) are dispatched automatically on consignment/payout transitions (`notify_seller_consignment_change`, `notify_seller_payout_change`). Admin operational inbox (`/admin/notifications`, `admin_operational_notifications`, `admin_notification_receipts`) emits capability-scoped alerts (`emit_admin_operational_notification`) for new/paid orders, failed/mismatched payments, new consignments, waiting authentications, pending payouts, import issues, and low stock (`lowStockThreshold`). External email/SMS provider delivery remains a development logger by design (Phase 39). |
| **Reports** | **COMPLETE** | `/admin/reports` (`admin_operational_report`) executes live SQL queries across 7 report types (`sales`, `orders`, `products`, `inventory`, `consignment`, `payouts`, `payment_failures`) with date range, currency, brand, category, and seller filters, plus CSV export. |
| **Audit** | **COMPLETE** | `/admin/audit` (`admin_audit_logs`) records actor, action, entity type, entity ID, timestamp, and non-secret metadata across all catalog, inventory, order, refund, payment reconciliation, consignment, authentication, payout, import, configuration, and staff role mutations. |
